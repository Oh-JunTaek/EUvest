## 상태: 진행 중 / 인수 미완료

기존 v1/v2 DB는 자동으로 새 계약에 이행하지 않는다. `legacy_reader.read_legacy_snapshot`은 별도 읽기 전용 트랜잭션으로 원본 값을 반환하며, 시각·자산·이력의 불명 값을 변환하지 않는다. 반환값은 민감할 수 있으므로 로그·외부 API 전송 금지. `contract_store.ensure_contract_db`는 신규 DB만 생성하거나 신규 계약을 검증하며 과거 DB는 거부한다. 기존 `storage.repositories`와 신규 계약은 자동 연결되지 않았다.

## 이번 보강

- v1→v2: SQLite backup API로 만든 백업의 무결성과 FK를 검사한다. 충돌하는 임시 테이블, 예상치 못한 열 구성·순서·타입·PK, 추가 UNIQUE 제약, 사용자 정의 인덱스/트리거, 외부 테이블의 FK가 있으면 롤백한다. 백업 직후 경쟁 쓰기와 재구성 중 쓰기 잠금도 검사한다. 알 수 없는 모든 SQL 제약을 완전하게 식별한다는 의미는 아니다.
- 새 저장 계약: `save_decision`과 `save_intent`는 `schemas/decision_proposal.schema.json`을 JSON Schema Draft 2020-12와 Pydantic으로 검사한다. 날짜 형식 검사기를 사용하며, UTC·run/state_version·종목·방향·통화도 확인한다. 무효 판단 원문은 저장하지 않고 실패 코드만 기록한다. 이는 위험 승인·계좌 대사·주문 제출이 아니다.
- 사용자가 승인한 `jsonschema[format-nongpl]`을 추가했다. 공식 검증기 문서: https://python-jsonschema.readthedocs.io/en/latest/validate/ (확인일 2026-11-04). 기본값에서는 형식 검사가 비활성일 수 있어 명시적으로 활성화한다.
- wheel 빌드에서 SQL 마이그레이션과 JSON 스키마 파일 포함을 확인했다. 설치된 wheel에서 실제 실행하는 검사는 아직 하지 않았다.
