## 원인과 변경

기존 v1 재구성은 새 자식 테이블이 기존 `decisions`를 참조하는 동안 그 부모를 삭제하여 외래키 오류가 났다. 파일 복사 백업은 WAL의 커밋 데이터를 놓칠 수 있고 실패 시 파일 덮어쓰기는 다른 연결의 쓰기를 손실시킬 수 있었다. 원본 테스트에서 재현했다.

SQLite backup API로 백업하고, 쓰기 잠금 획득 후 `data_version`을 확인하여 백업 중 다른 연결의 변경을 감지하면 중단한다. 외래키를 끈 재구성은 명시적 트랜잭션으로 수행하고 커밋 전 외래키를 검사하며 실패 시 롤백한다. 대상 테이블 부재 및 지원하지 않는 버전은 거부한다. 임시 DB 테스트에서 전체 행 비교, 백업 내용, WAL, 실패 주입 및 백업 직후 경쟁 쓰기를 확인했다.
