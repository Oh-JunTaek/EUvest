# P1-09 점검 및 P1-10 인계 — 2026-11-07

## 판정

**P1-10을 안전한 실행 흐름으로 연결하기에는 선행 결함이 남아 있다.** 아래 결함 수정과 Mock 통합 검증 전에는 주문 경로를 연결하거나 LIVE/PAPER 가능 상태로 보고하지 않는다. P1-09의 실제 OpenDART 연결·기타 출처·AI 요약은 완료가 아니다. 신규 조사 결과의 `metadata.status == BLOCKED`는 장애/미지원이며 AI의 정상적 NO_TRADE가 아니다.

## 이번 P1-09 보완

- 계획별 예산을 분리하고 실제 호출 전에 1회씩 소비한다. 오류는 근거 객체로 위장하지 않고 상태 코드로 표시하며 예외 문자열·인증키를 결과에 넣지 않는다.
- 허용되지 않은 출처는 `UNSUPPORTED`, 클라이언트 미설정·식별자 불명·예산 초과·발표 시각 미확인은 각각 차단한다. 기본 계획 생성으로 외부 클라이언트를 생성하거나 호출하지 않는다.
- 서로 다른 수치·출처를 잘못 중복 처리하지 않고, 시간대 없는 날짜/임의 생성일은 발표 시각으로 취급하지 않는다. 부분 문자열 필터는 주입 방지 보장이 아니다. 미검증 원문을 AI에 전송하는 기존 요약 경로는 중단하고 수집 건수만 표시한다.
- DART `report_nm`, 8자리 `corp_code`, 종목코드 대조를 반영했다. `list.json`의 접수일은 날짜만 제공하므로 발표 시각이 따로 검증되지 않으면 거래용 근거로 만들지 않는다. 여러 페이지가 필요한 결과는 불완전 성공으로 처리하지 않는다. `document.xml`은 ZIP이므로 처리 미구현으로 표시한다.
- `httpx`는 INFO 로그에 요청 URL을 기록하고 OpenDART는 인증키를 쿼리로 요구한다. 키 유출 방지 및 별도 승인 검증 전 `DartClient`의 실제 네트워크를 차단하며 MockTransport만 허용한다. 이는 실제 API 연동 완료를 뜻하지 않는다.

공식 근거: [OpenDART 공시검색](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019001), [고유번호 파일](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019018), [공시서류 원본 ZIP](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019003) (2026-11-07 확인). `httpx/_client.py`의 HTTP Request INFO 로그도 로컬 설치본에서 확인했다.

## P1-10 실행 연결을 막는 선행 작업

| ID | 확인된 사실 | 필요한 후속 검증 |
|---|---|---|
| P10-BLOCK-01 | `Order.transition_to`가 없는 `OrderStatus.SUBMITTED` 참조 후 `AttributeError`를 내며 상태를 먼저 변경한다. `Order.fill`은 두 번째 체결에서 수량을 두 번 더하고, 상태 전이표는 명세의 UNKNOWN 복구/종결 상태와 다르다. `sizing.py`는 정의된 `1 market_currency = fx_rate base_currency`와 반대로 환산하며, `RiskGate`는 매도 수량 전체와 실제 보유를 대조하지 않고 `allow_short=True`도 허용한다. | P0-06을 별도 수정: 상태/감사 원자성, 부분체결, 통화별 현금·FX, 초과 매도, timeout 재조회, 가상 broker 재시작 회귀. 실제 주문 없음. |
| P10-BLOCK-02 | `AIResponse`는 frozen인데 `ProviderRouter.generate`가 `response.content`를 직접 대입한다. 외부 연결 없는 FakeProvider 재현에서 `RuntimeError: All providers failed: cannot assign to field 'content'`. 현재 fallback 경로도 설정을 확인하지 않으며 입력 비밀 검증이 호출 전에 적용되지 않는다. | P0-07을 별도 수정: Fake 동작, 승인된 fallback만, 동일 state_version, 입력 전송 전 비밀 차단 및 429/timeout 테스트. |
| P10-BLOCK-03 | 임시 DB의 `ContextBuilder.build_context`에서 없는 `DecisionRepository.get_recent_runs` 호출로 `AttributeError`. 구 `storage.repositories` 사용으로 P0-03의 새 `contract_store`와 호환되지 않는다. `_get_open_orders()`는 빈 목록을 반환하고 `HandoffSnapshot.to_dict`는 클래스 바깥에 있다. | P0-08을 별도 수정: 신규 계약 저장소 연결, 열린 주문·가설·state_version 유지, 개인정보 제거 및 A→B→A/재시작 검증. 구 DB는 보존. |
| P10-BLOCK-04 | 현재 P1-09 실제 수집은 차단돼 있고, `CollectedEvidence`는 구 `domain.models.Evidence` 타입이다. 신규 `contract_store.EvidenceInput`으로의 출처·시간·자산·해시 변환과 원자 저장이 연결되지 않았다. | 검증된 매핑과 시각·출처를 갖춘 P1-09→P0-03 연동 테스트. 미확인이면 BLOCKED. |

이 목록은 코드 확인과 위 두 예외의 오프라인 재현을 바탕으로 하며, 전체 투자 안전성에 대한 독립 감사 완료를 뜻하지 않는다. 새로운 Phase나 실계좌 연결을 승인하는 내용도 아니다.

P10-BLOCK-01 추가 재현은 모두 임의 숫자와 메모리 객체만 사용했다. 기준 통화 1,300,000원, 목표 10%, 주가 100달러, 환율 1달러당 1,300원이면 목표 수량은 1주이지만 현재 `calculate_sizing`은 1,690,000주를 반환했다. 또 `RiskGate.check_order`는 보유 2주, 매도 3주인 fixture에 `PASS`를 반환했다. 현재 저장·주문 경로에 사용하면 안 된다.
