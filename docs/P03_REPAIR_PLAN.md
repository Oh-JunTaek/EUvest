- 미확인 API: 없음. 모든 검증은 임시 DB에서 수행한다. 실행기/실제 주문과 연결하지 않는다.

## 추가 보강 계획

- 기존 v1→v2 경로에서 임시 테이블 충돌, 열 순서 차이, 재구성 시 사라질 사용자 정의 인덱스·트리거와 다른 테이블의 외래키를 발견하면 롤백한다. 대상은 `storage/schema.py`와 임시 DB 기반 테스트다.
- 신규 계약의 판단 저장 경로는 버전 관리된 JSON Schema와의 검증 및 위험 검증이 연결되기 전 거래 승인을 의미하지 않는다. 미확인 API·실계좌 호출 없음.
- 사용자 승인에 따라 `jsonschema` 검증 라이브러리를 추가한다. `schemas/decision_proposal.schema.json`을 직접 읽어 형식까지 검증하고 Pydantic으로 시각·판단 연결을 검사한다. 실제 위험 검증과 주문은 범위 밖이다.
- 과거 DB는 명시적인 읽기 전용 연결로 일관된 스냅샷을 읽는다. 원본 파일·버전·데이터 보존과 미지원 스키마 거부를 임시 DB에서 확인하고, 새 필드로 자동 이행하지 않는다.
- 유효한 판단을 저장하는 공개 경로는 원본 스키마/Pydantic 검증, UTC, 실행과 상태 버전 일치를 원자적으로 확인한다. 무효 판단 저장 및 후속 위험 게이트는 미구현으로 분리한다.
- 신규 저장소 진입 경로를 명시적으로 제공한다. 빈 경로만 생성하고 기존 파일은 버전·테이블·무결성을 확인하며 기존 DB를 자동 변환하지 않는다.

## P0-03 인수 마무리 계획

- 신규 DB의 필수 실행 흐름을 직접 SQL 없이 검증된 자산·실행 생성, 판단·intent 저장과 재시작 후 조회로 연결한다. Pydantic, Decimal, UTC와 자산 식별 제약을 적용한다.
- 가설 저장과 상태 버전 갱신을 같은 트랜잭션으로 묶고, 이전 버전 보존·경합·실패 롤백을 검사한다. 브로커 주문과 RiskGate 구현은 해당 후속 티켓에 둔다.
- 증거 DTO와 저장을 추가하고 자산 참조·관측/수집 시각을 검증한다. 증거 추가도 상태 버전을 갱신해 이전 판단을 stale로 만든다.
- 테스트: 빈 DB→자산/실행/판단/intent→재연결 조회, 중복·stale·금지 입력, 가설 버전 보존, 기존 DB 읽기 전용 및 마이그레이션 복원. 전체 pytest·Ruff와 인수 기준별 미검증 사유를 기록한다.
- DB 파일 무결성뿐 아니라 마이그레이션 SQL과 실제 테이블·인덱스·트리거 정의를 대조해 감사 트리거나 유일 제약이 누락되면 쓰기를 거부한다.
